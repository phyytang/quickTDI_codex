## 2. 测试目标

1. 验证 quickTDI 从轨道、GW、光学平台、锁定、信号合成到 TDI 的端到端链路功能正确。
2. 验证臂映射、时延算子、GW 线性响应和 TDI 激光噪声消除等关键物理约束。
3. 验证随机噪声在固定随机状态下可复现，其均值、方差和功率谱特征符合定义。
4. 验证非法输入、缺失前置状态和异常数据能够产生明确、稳定的错误。
5. 验证推断工具的先验、PSD、似然和命令行入口在受控数据上正确运行。
6. 建立可自动执行、可追溯、可复现的回归测试和性能基线。

## 4. 测试策略

### 4.1 测试层级

1. 单元测试：函数、类方法、映射、边界和异常路径。
2. 组件测试：`orbit + gw`、`ob + lock`、`synthesis + tdi` 等模块协作。
3. 集成测试：`Triangle` 全流程和推断脚本。
4. 回归测试：固定参数、固定随机种子和版本化参考结果。
5. 性能测试：固定规模下记录耗时与峰值内存，检测明显退化。

### 4.2 测试类型

- 功能与接口测试
- 物理约束和数值一致性测试
- 边界、异常和数据校验测试
- 统计特征和功率谱测试
- 状态转换与重复调用测试
- 安装、兼容性和命令行测试
- 稳定性与性能基线测试

### 4.3 测试方法与判定原则

- 使用 `pytest`；共享对象和数据通过 fixture 构造。
- 精确映射、长度、标签和固定随机状态使用精确比较。
- 浮点结果使用逐用例定义的 `rtol`、`atol` 或归一化误差，不使用未说明容差的“近似相等”。
- 对理论零值，容差必须依据输入尺度定义，不能直接依赖 `numpy.allclose` 默认值。
- 随机过程同时采用固定种子复现和统计区间判定；不得用单次样本判断谱形。
- 统计测试固定样本长度、采样率、频段、窗函数和允许置信区间。
- 端到端数组比较时排除最大复合时延和插值阶数引起的边界保护区。
- 物理正确性优先使用独立公式、标量参考实现或解析极限作为测试 Oracle；历史数组仅用于回归，不作为唯一正确性证据。
- 所有失败必须保存输入参数、随机种子、Python/依赖版本和必要日志。

### 4.4 通用数值约定

以下为默认值；若具体用例另有规定，以具体用例为准。

| 比较类型 | 默认判定 |
|---|---|
| 常量和映射 | 精确相等 |
| 时间轴与常臂时延公式 | `rtol=0`、`atol=1e-12 s` |
| 位置、速度、臂长参考值 | `rtol=1e-10`、`atol=1e-12`，并记录单位 |
| GW 线性关系 | `||y-(y1+y2)||₂ / max(||y1+y2||₂, ε) <= 1e-10` |
| 回归数组 | 使用版本化基线给出的逐项容差 |
| 理论零信号 | 使用相对于输入 RMS/PSD 的归一化残差阈值 |

TDI 和锁定的最终抑制阈值应由理论模型或经评审的基准实验确定，并写入回归基线文件；阈值未确认前，相应用例不得作为正式验收通过项。

抑制指标统一定义为：

- 时域归一化残差：`R_rms = RMS(output) / max(RMS(reference_input), ε)`；
- 频域功率比：`R_psd = median(PSD_output / PSD_reference)`，只在基线规定的有效频带内计算；
- 抑制度：`D_dB = -10*log10(R_psd)`。

基线必须同时记录有效频带、边界保护区、窗函数、分段长度和参考输入，避免不同配置得到的指标被直接比较。

## 5. 测试环境

### 5.1 环境矩阵

- 项目声明的最低版本：Python 3.9（见 `pyproject.toml`）。
- 必测环境：Linux + Python 3.9、Linux + 一个当前维护的 Python 版本。
- 开发环境冒烟：macOS + 开发者当前 Python 版本。
- 兼容性扩展：Python 3.10 至 3.14；其中未进入 CI 的版本标记为“未验证”，不能标记为正式支持。
- 核心依赖：`numpy`、`scipy`。
- 推断可选依赖：`dynesty`。

每份测试报告必须记录操作系统、CPU 架构、Python、NumPy、SciPy、dynesty 和 quickTDI 版本。依赖不得只写“最新版”。

### 5.2 安装与执行命令

```bash
python3 -m pip install numpy scipy pytest pytest-cov
python3 -m pip install -e .
python3 -m pip install -e .[inference]
PYTHONPATH=src python3 -c "from TJ_Triangle import Triangle; Triangle(t_end=40)"
pytest -q
```

### 5.3 共享测试数据要求

- 光学平台采用 31 阶插值，小型 fixture 必须至少包含 32 个采样点。
- 文件轨道采用三次插值，CSV 至少包含 4 个严格递增且不重复的时间点。
- positions CSV：`time + 3×3`，共 10 列。
- velocities CSV：`time + 3×3`，共 10 列。
- distances CSV：`time + 6 arms`，共 7 列，臂顺序为 `[3,-2,-3,1,2,-1]`。
- 多文件轨道数据必须使用一致的时间轴、行数和单位。
- 推断 NPZ 必须记录 `t` 和所请求的通道；模型时长、采样率和数据长度必须一致。
- 参考数据需附生成脚本、参数、随机种子、版本和校验值。

## 6. 入口与退出准则

### 6.1 入口准则

1. 待测版本和代码范围已冻结并可导入。
2. 测试环境、依赖版本和可选依赖状态已记录。
3. 测试数据、参考结果、容差和物理阈值已经评审。
4. 高优先级用例具备可执行步骤和明确预期结果。
5. 已知限制和本阶段排除项已经确认。

### 6.2 退出准则

1. 所有 H 级用例、端到端用例和关键物理正确性用例 100% 通过。
2. 不存在未关闭的 S1/S2 缺陷；S3 缺陷必须有风险接受记录和回归计划。
3. 全部自动化用例通过率不低于 95%，且不得用低优先级用例稀释核心失败。
4. 支持环境的安装、导入和最小运行检查全部通过。
5. 已形成测试报告、覆盖报告、缺陷清单、性能结果和回归基线。
6. 未确定验收阈值、缺失 Oracle 或数据不可追溯的核心用例不得计为通过。

## 7. 优先级、缺陷分级与处理

### 7.1 测试用例优先级

- H：核心物理结果、主流程、数据完整性和阻断性异常。
- M：重要分支、兼容性、统计特征和一般异常。
- L：低风险辅助接口、性能观察和文档一致性。

### 7.2 缺陷严重度

- S1：主流程不可用、结果整体错误、数据损坏或无法完成测试。
- S2：核心功能或物理结果错误、无可靠替代路径。
- S3：一般功能或边界行为错误，有明确替代路径。
- S4：低风险可用性、日志、文档或优化问题。

### 7.3 处理要求

1. 缺陷记录必须包含用例 ID、输入参数、随机种子、环境、复现步骤、预期、实际、日志和证据文件。
2. 修复 S1/S2/S3 缺陷后必须增加自动化回归测试。
3. 数值缺陷必须说明误差度量、影响频段、数据范围和物理影响。
4. 延期缺陷必须记录责任人、计划版本和风险接受人。

## 11. 性能与稳定性测试

### 11.1 性能基线

固定以下输入后记录中位耗时、95 分位耗时和峰值内存：

- `Triangle` 初始化
- 单源 GW 对象创建
- 六个 bench 初始化
- single/dual/common 锁定
- synthesis delay level 0/1
- X1/X2 单通道 TDI
- 单次 likelihood

首次稳定版本的结果作为基线。相同机器和依赖环境下，耗时或内存恶化超过 20% 时标记为性能回归候选，由人工确认；不得跨不同硬件直接判定失败。

### 11.2 稳定性

- 同参数、同随机种子重复运行 10 次，确定性数组应精确一致或满足指定容差。
- 不同种子重复运行时，统计量和 PSD 应落入约定区间，而非数组相同。
- 使用 `t_end=1e5` 的长时冒烟测试检查无崩溃、无 NaN/Inf 和无异常内存增长。
- 对多源数量和最长预置 TDI 通道做规模递增测试，记录时间和内存趋势。

## 12. 需求追溯、报告与证据

### 12.1 追溯矩阵

维护“需求/风险 → 模块 → 用例 ID → 自动化测试函数 → 最近结果 → 缺陷 ID”的映射。至少覆盖：

- 时延算子
- GW 线性响应
- 噪声统计模型
- 激光锁定
- TDI 激光噪声消除
- 推断似然
- 安装与兼容性

### 12.2 测试报告最小内容

1. 待测版本、环境和依赖清单。
2. 执行范围、排除项及原因。
3. 用例总数、通过/失败/阻塞/跳过数量。
4. H/M/L 用例分别的通过率。
5. 关键物理指标、容差、PSD/RMS 图和基线比较。
6. 缺陷清单、严重度、状态和风险接受记录。
7. 性能与内存结果。
8. 结论：通过、有条件通过或不通过。

### 12.3 回归基线管理

- 基线文件必须包含生成参数、随机种子、单位、代码版本、Python/依赖版本和校验值。
- 基线更新必须说明数值变化原因，并由不同于修改者的人员复核。
- 不允许仅为使失败测试通过而无依据地放宽容差或覆盖基线。

## 13. 风险与应对

- 随机噪声造成偶发失败：固定种子用于复现，统计置信区间用于正确性判定。
- 浮点和 SciPy 插值在平台间有差异：逐项定义容差，记录平台并排除边界保护区。
- 高阶插值需要足够样本：fixture 至少 32 个 OB 点，文件轨道至少 4 点。
- 时延和通道定义耦合：先验证映射和单臂时延，再验证复合时延和完整 TDI。
- 历史基线可能固化错误：物理用例必须同时具有解析、独立公式或标量参考 Oracle。
- CLI 时长与输入数据不一致：测试数据严格匹配配置；后续为 CLI 增加显式时长参数。
- 推断测试耗时过长：分离数据校验、likelihood 测试和低频 dynesty 闭环。
